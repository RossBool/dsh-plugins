# Product

## Register

product

## Users

- 主要用户：一位在 DeepSeek Harness Web GUI（本地 http://127.0.0.1:3080）中做语音驱动编程的开发者。
- 场景：不想打字/双手不在键盘上时，点击输入框右侧麦克风按钮口述需求；录音自动停止后，转写（可选 LLM 增强）自动填入当前会话输入框。
- 辅助用户：需要通过 agent 工具（voice_listen / voice_ask / voice_transcribe）用语音与 agent 交互的同一使用者。

## Product Purpose

在聊天输入框提供零学习成本的语音输入：点按钮说话 → 静音自动停止 → 转写/增强 → 回填草稿，全程无需离开输入区。
成功标准：从点击到草稿可发送，每一步状态可见、无惊吓、无阻塞；任何失败都能在按钮旁看到原因和下一步建议。

## Brand Personality

无独立品牌。视觉与交互完全继承 DeepSeek Harness GUI 的设计体系（`--dsw-*` token、中性底色、品牌蓝）。
人格：安静、精确、克制——工具感，不拟人、不表演。

## Anti-references

- 录音态不得呈现「报警感」：红点 + 红边 + 红底叠加（读起来像报错，不像「正在听」）。红色只留给错误态。
- 不得把关键状态藏在 hover/tooltip 里（录音秒数曾经只存在于 title 属性）。
- 不得使用独立色板或硬编码颜色脱离宿主 token 系统（曾使用不存在的 `--ds-color-*` 变量导致主题失效）。
- 不得在 30px 按钮里塞下所有状态信息（电平条、秒数、停止提示挤成一团）。

## Design Principles

1. 状态永远可见：启动中 / 录音中 / 识别中 / 错误，都必须直接呈现在画面上，不依赖 hover。
2. 借用宿主语言：颜色、字体、圆角、动效全部取自 DSH GUI token，不发明新视觉语言。
3. 反馈即时且可预期：电平跟随音量，时间推进，静音自动停止有明确提示，用户随时知道下一步会发生什么。
4. 错误是信息不是警报：错误用错误色 + 原因 + 建议；录音进行中绝不使用错误色。

## Accessibility & Inclusion

- WCAG AA 对比度：正文 ≥4.5:1，大字（≥18px 或粗体 ≥14px）≥3:1；占位/次级文字同样达标。
- `prefers-reduced-motion: reduce` 下声波动效降级为静态指示。
- 状态不只靠颜色传达：图标 + 文字双通道。
